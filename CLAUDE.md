## Hardware and status
- Raspberry Pi 3B+ (Raspberry Pi OS, Python 3.13), Bangle.js 2 watch, SNOOZ white noise machine, Adafruit NeoPixel RGBW strip (SK6812, 60 LEDs, GRBW) on SPI0 MOSI (GPIO10, pin 19) through a 74AHCT125, with its own 5 V 4 A supply (wiring in README). DS3231 clock not installed yet.
- Working: SNOOZ control (`snooz/`), watch app + Pi logger (`watch/`), phone web app with diary (`web/`), sleep analysis (`analysis/`), smart alarm service (`wake/`), LED sunrise (`sunrise/`, strip tested by hand October 2026). Watch charge control (`charge/`, written October 2026, not yet run on the Pi: the uhubctl switch, the advert scan and the watch's motion gate all need the hand checks in `docs/watch-charging-design.md`; `install.sh` installs `sleepcharge` disabled and only restarts it once the owner has enabled it). The movement thresholds (`active_floor`, `active_ratio`) were set from the first real night, 2026-10-14; the others still have no real nights behind them.
- Alarm semantics (owner's choice, October 2026): `alarm_time` is the time to be awake by. From `alarm_time - window_minutes` the SNOOZ fade starts at the first light-sleep sign, otherwise at `alarm_time - fade_minutes` (a window no longer than the fade means no watching: the fade starts when the window opens); the fade ends by `alarm_time`; the watch buzzes at `alarm_time` as the last resort, with the watch's own built-in alarm as a backup. The SNOOZ fade is the wake stimulus, not the buzz. The sunrise light runs on its own fixed clock (`sunrise_times()`): a 30-minute ramp ending at `alarm_time`, independent of the detection, held at peak for 60 minutes; it stops early only from the web app's light-off button or when the alarm is switched off, not on the watch button (owner's choice, October 2026, following the dawn-simulation protocol in `docs/`).

## Conventions
- The owner runs every command on the Pi himself over SSH. Give exact copy-paste commands, and keep `install.sh` idempotent so updating is always `git pull && ./install.sh`.
- Code lives in `~/sleeptracker/code`; data, settings and device secrets live outside the repo (see the README table). Never commit sleep data, `snooz.json`, `bangle.json`, IP addresses, usernames or emails: the repo is public.
- Bluetooth Python runs in `~/snooz-env`. `pysnooz` is pinned to 0.10.0: there `set_volume()` takes no duration; fades use `turn_on(volume, duration)` / `turn_off(duration)`.
- The watch accepts one Bluetooth connection at a time, so `watch_logger.py` is started by hand, not as a service (an always-on logger would lock out the Web IDE and phone). It is also the only process that talks to the watch: `wake.py` asks for a buzz through `~/sleeptracker/watch-cmd.json` and reads `~/sleeptracker/watch-status.json`.
- The watch's dock is powered from the Pi's USB ports, and `charge.py` (the `sleepcharge` service, in `~/snooz-env`) is the only thing that switches them, through `uhubctl` (a Pi 3B+ switches all four ports together, so nothing else may be powered from them). It never connects to the watch: it reads the level from the watch's advertisement, or from `watch-status.json` while the logger is connected. Off at `charge_max`, on at `charge_max - 10`, on whenever unsure, and on whenever the watch reports it is recording or was stopped by hand (only a live charger ends either). The watch app only starts recording after it has moved, because a dock with its power cut looks like being taken off (owner's choice, October 2026).
- During an alarm `wake.py` is the only process driving the LED strip, through a `sunrise.py run` subprocess that is a pure function of the clock (so a restart resumes it). The web app (system python3, no LED library) asks for the light to go off through `~/sleeptracker/light-cmd.json`. Brightness is capped by estimated current (`max_amps`, default 3.0 for the 4 A supply).
- `analysis/sleep_analysis.py` is the single source of truth for light-sleep detection: the web chart overlay and the live alarm must go through the same `Detector` so they agree. Thresholds are named tunables with defaults, overridable from `settings.json` under `tuning`. Standard library only (the web app runs under the system python3).
- Tests: `python3 -m unittest discover -s tests -v` from the repo root; no packages needed. `analysis/make_test_night.py` makes a synthetic night for the web app and tests.
- Watch app: edit `watch/src/`, then run `python3 watch/build_installer.py` and commit both.
- Show times on a 12-hour clock in anything user-facing.
- Tasks are tracked in Linear with numbered titles (1.x before parts arrived, 2.x after); keep that numbering for new tasks.
